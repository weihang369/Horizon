**Search timing (task 6.3).** On a test database holding 3,000 pieces for one character, every one with a stored
vector, and a worst case where every query word is in every piece (`test_search_timing_m12.py`, 110 searches each):

| Search | p50 | p99 |
|---|---|---|
| keywords only (no query vector) | 30 ms | 46 ms |
| keywords and two dense texts | 56 ms | 69 ms |

The target was 50 ms at p99. What costs, measured step by step:
- each flat KNN over the partition is ≈ 11 ms (two dense texts: 22 ms);
- the 20 stored vectors MMR compares cost ≈ 19 ms;
- FTS costs ≈ 9 ms;
- MMR itself costs ≈ 2 ms, after making it incremental.

Reading a vector back from sqlite-vec is the slow part:
- by key, ≈ 1.5 ms each;
- as an `IN` list, ≈ 20 ms (a partition scan);
- with the KNN query, +19 ms;
- as one statement of key lookups (what ships), ≈ 19 ms for 20.

Dense searches miss the target by about 20 ms. The test guards keyword searches at 50 ms and dense ones at 100 ms
until the user decides.

**Findings while building:**
- **A search that matches nothing is "not found".** Jev call 2 never runs and nothing failed. It was a fallback in the
  first build, which left a debate turn on an unrelated motion with no trace.
- **In 1:1 a new message queues behind the reply; it doesn't supersede it.** M7 built it that way. Stop (`clear()`) is
  1:1's cut for the rewrite and the checks; in group a newer message cancels the deep work (G5). The storms cover both.
- **The near-copies scenario was stronger than MMR at λ 0.7 guarantees.** The retrieval spec said "at most one of the
  top 3 copies among the 8". MMR pushes a copy down only below pieces of relevance ≳ 0.56. The scenario now says what
  MMR does: with seven others of similar relevance, at most one copy is kept. λ is still compared in phase 11.
- **A director's note drops the plan made ahead's deep work at once.** That plan is stale anyway (its fingerprint
  holds the note), and dropping it now records its checks `cancelled` instead of `late`. M10's own plan still runs out
  as M10 left it.
- **Test doubles.** The fake answers every "needs documents?" no unless a test sets it, and a queued streamed reply
  waits for a chat request, so the gate questions riding a plan don't take it. A held embedding gives up its activity
  token, so virtual time can pass the 400 ms wait.
