# Design: backend-foundation (M1b)

## Context

See `proposal.md` for the motivation. The design pack (`docs/backend/01`–`06`) fixes the architecture, so this document only covers the choices the pack leaves open and the places where the pack and the code disagree.

What exists today:
- **Frontend.**
  - The MockClient is the only client.
  - `client/index.ts` hard-codes it.
  - The UI's "Reset demo data" buttons call `mockActions.resetDemoData()`, which is the mock-only `dev` API.
  - `HorizonClient` has no `admin` namespace.
- **Contract.** `backend/horizon/contract/schema.json` (52 `$defs`) is generated by `npm run export-schema` and checked for drift.
- **Shared fixtures.** `backend/tests/fixtures/energy/cases.json` and `reducer/*.json` (6 cases) are consumed by the TS tests only.
- **Seed.**
  - Files are wrapped as `{ schemaVersion: 1, data }`.
  - There are 2 worlds, 6 characters, 5 sessions (Meridian has only **2**), knowledge, memory, songs and `usage/ledger.json`.
  - `seed/_mock/**` holds the mock-only overlays: 5 characters including archived Mochi and draft Sarah, 6 sessions, 2 jobs, a song, ledger rows and scenario variants.
  - **The MockClient's default dataset is seed + `_mock`**, and the portable suite's assertions rely on it: "≥ 5 Meridian sessions", "an archived Sunny Hollow character", `chr_mockSarah`.
- **Portable suite.** It has about 50 tests, and almost all of them need writes, a key or AI. In M1b only a handful can run against the backend.
- **Toolchain.** Node 24 (no global `EventSource`), uv 0.11 and system Python 3.13. There is no CI workflow.
- **Vercel.** `vercel.json` pins the install and build to `frontend/`, so a root `package.json` doesn't affect it.

## Goals / Non-Goals

**Goals:**
- A backend whose read model is **byte-for-byte the seed**: every seed entity read from the API equals its seed file, after timestamp normalisation and read-time derivations.
- One source of truth for wire shapes: `schema.json`.
- Every later milestone adds routes and HttpClient methods without reworking M1b's engines, unit of work, event bus, error envelope or test harness.

**Non-Goals:**
- Anything that writes characters, sessions, the ledger or energy.
- Key handling.
- Docling installation or models.
- Embeddings (the vec tables exist but stay empty).
- Changing `VITE_HORIZON_CLIENT` defaults.
- Running E2E against the backend.

## Decisions

### D1. `schema.json` is the only wire schema; responses are dicts, requests are Pydantic
- **Responses.**
  - Response bodies are plain dicts assembled by mapper functions (`contract/mappers/*`) from columns and the JSON columns, which are already stored in wire form (doc 02 §1).
  - `contract/validate.py` validates a dict against a `$def` with `jsonschema` (Draft 2020-12, `$ref` → `#/$defs/…`).
  - Under `HORIZON_TEST=1`, a response-validation hook checks **every** JSON response and SSE payload against the route's declared `$def`, and any failure turns into a 500 in tests. This is how "every response validates" is enforced across the whole suite instead of being sampled.
- **Requests.** Request bodies (`WorldInput`, the reset confirmations, `/_test/*`) are small Pydantic v2 models with camelCase aliases.
- **OpenAPI.** The route response schemas in OpenAPI are injected from `schema.json` `$defs`, so `/api/docs` shows the real shapes.
- **Rejected alternatives.**
  - *Pydantic models for all 52 defs, hand-written:* this duplicates the zod source, which is guaranteed to drift.
  - *Generated with datamodel-code-generator:* this adds a codegen step and still needs jsonschema for the SSE payloads.

### D2. Database access: two engines, one writer lock, a unit of work that publishes after commit
- **Writer engine.**
  - `create_async_engine("sqlite+aiosqlite:///…")` with `pool_size=1`, `max_overflow=0`.
  - `isolation_level=None` on the DBAPI connection.
  - A `begin` event that emits `BEGIN IMMEDIATE`.
- **Reader engine.** A small pool, used for read-only `BEGIN DEFERRED` transactions.
- **On connect, both engines:**
  - set the pragmas (`journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, `busy_timeout=5000`);
  - load sqlite-vec through `AdaptedConnection.run_async(lambda c: c.enable_load_extension(True); c.load_extension(sqlite_vec.loadable_path()))`. Spike (a) proves this.
- **`db/uow.py`.**
  - `async with uow.write() as tx:` takes the process-wide `asyncio.Lock`, opens the writer transaction, and collects events through `tx.publish(event)`.
  - The events go to the EventBus **only after a successful commit**, and are dropped on rollback.
  - `uow.read()` uses the reader engine.
  - Nothing awaits the network while holding the lock (enforced by convention, and trivially true in M1b).
- **Rejected alternative:** a single engine with `StaticPool`. It serialises reads behind writes and breaks SSE replay during a reset.

### D3. Migration `0001_initial` is written by hand; the ORM models mirror it
- SQLAlchemy 2.0 declarative models (`db/models/`) cover every ordinary table in doc 02 §3, with `rid INTEGER PRIMARY KEY` + `id TEXT UNIQUE` on `memory_items` and `knowledge_chunks`.
- `0001_initial` creates the tables with `op.create_table`. It creates the FTS5 external-content tables and their INSERT/UPDATE/DELETE triggers with `op.execute`.
- `include_object` skips `*_fts*` and `*_vec__*` objects.
- A test runs Alembic autogenerate against a migrated database and asserts that the diff is empty.
- **Rejected alternative:** `metadata.create_all` at startup. It can't evolve, and it hides drift.

### D4. The SpaceManager owns the vec tables
- The default space row is `qwen3-emb-8b@1024`: model `qwen/qwen3-embedding-8b`, provider Nebius, 1,024 dims, float32, normalised.
- At startup, `spaces.ensure_active()` creates `memory_vec__{space}` and `knowledge_vec__{space}` (vec0, `character_id` partition key, cosine distance) plus `AFTER DELETE` triggers on `memory_items` / `knowledge_chunks` that delete by `rid`.
- The DDL is idempotent (`IF NOT EXISTS`, with the triggers created per space).
- The final model and dimension count belong to the AI stage. Changing them is a space switch (doc 02 §3.9), so 1,024 is a safe default rather than a lock-in.

### D5. The seed import maps the seed into rows, and a round-trip test proves the reverse
- `services/seed.py` runs in a single writer transaction:
  1. load every `seed/**.json` except `_mock`. In test mode, the default-scenario `_mock` overlays are loaded too (D13).
  2. unwrap `data`;
  3. validate each entity against its `$def`;
  4. normalise timestamps to `.mmmZ`;
  5. insert with `is_seed = 1`.
- **Characters.**
  - The `emotions`, `basePortraitUrl` and blink entries become `image_assets` rows (`kind='emotion'`, `is_active=1`, `version=1`, `rel_path` = the `/assets/placeholder/...` path, `format` omitted for SVG).
  - `appearance.candidates` become `kind='candidate'` rows with `job_id NULL`, which is the seed batch (doc 02 §3.2).
  - Energy goes into the energy columns.
- **Sessions.**
  - The events are inserted, the Python reducer (D6) reduces them, and the result is **asserted equal** to `messages.json`.
  - The reduced messages are what gets inserted. On a mismatch, the whole transaction aborts and the error names the session.
  - Traces from `insight` events go to `turn_traces`.
  - Citations go to `message_citations`.
- **Knowledge.**
  - Each seed chunk gets one synthesised section (parent text = child text).
  - Chunks keep their seed IDs and locators.
  - FTS is populated by the triggers.
  - A seed `status` of `indexed` is stored as `keyword_only`, because there are no vectors (doc 02 §5 and OQ-1). `failed` is kept, along with its `error`.
- **Memory.** Inserted with `is_seed = 1`, and FTS is filled by trigger.
- **Ledger.** `usage/ledger.json` rows are inserted with `is_seed = 1`, and `local_day` is computed in `HORIZON_TZ`.
- **Round-trip test (the main acceptance test for the read model).** For every seed entity, `GET` from the API must equal the seed file after:
  - timestamp normalisation;
  - the read-time derivations (`World.characterCount`, `Energy.state` / `fullAt`, `KnowledgeSource.citedCount` and `status`);
  - nothing else.

  Any field the mappers drop or invent fails this test.

### D6. `reducer.py` is a literal port that works on wire-shaped dicts
- It ports `initialRuntime`, `applyEvent`, `reduceAll` and `orderedMessages` from `sessionReducer.ts` one function at a time, operating on plain dicts (the wire shapes) rather than ORM objects.
- That keeps the comparison with fixtures and `messages.json` a straight JSON-equality check after a `plain()` round trip, the same check the TS fixture test uses.
- The module has no I/O, and mypy runs in strict mode on it.
- Where TS relies on `undefined` (an absent key) versus `null`, Python uses an absent key. Every divergence found during the port gets a new shared fixture, so both languages stay pinned.

### D7. `domain/energy.py` is a full port now, used read-only in M1b
- Every function covered by the shared fixtures is ported: `points_for_cost`, `regen_at`, `energy_state`, `drain`, `top_up`, `settle`, `day_roll`, `can_top_up`, `to_wire_energy`, `full_at`. It is ~120 lines, and the fixtures already exist (OQ-2).
- The character read uses `settle(e, now, frozen=demo_mode)` followed by `to_wire_energy`. In M1b demo mode is always on (OQ-3), so energy is frozen as stored, and only `state` / `fullAt` vary with the pricing period.
- M2 adds the writes (drain, top-up) on top of the same module.

### D8. The Clock and pricing
- `domain/clock.py` provides:
  - a `Clock` protocol with `now()`, `today_start()`, `pricing_period()`, `next_change_at()` and `sleep()`;
  - a `SystemClock`;
  - a `FrozenClock` (set/advance, where `sleep` advances virtual time).
- The peak windows (Mon–Fri 09:00–12:00 and 14:00–18:00 in `HORIZON_TZ`, default `Asia/Kuala_Lumpur`) come from config and match `pricing.config.ts`.
- `/_test/clock` swaps the system clock for a `FrozenClock`.
- `zoneinfo` needs the `tzdata` package on Windows, so it is a dependency.

### D9. EventBus and SSE
- **`events/bus.py`.** An in-process pub/sub with channels `global` and `session:{id}`. Each subscriber is an `asyncio.Queue(maxsize=1000)`. If `put_nowait` fails, that subscriber is marked dropped and its stream closes.
- **`events/sse.py`.** Uses sse-starlette's `EventSourceResponse` with `ping=15` and the headers `Cache-Control: no-cache` and `X-Accel-Buffering: no`.
- **Session stream.** Follows doc 03 §4 exactly:
  1. register the queue;
  2. compute `start = max(sinceSeq, Last-Event-ID)`;
  3. replay stored events in pages of 200, each page in its own short read transaction;
  4. drain the queue, skipping `seq ≤ lastSent`.
- **Frame format (decided during apply).** A session frame's `data:` is the whole `SessionEvent`, not just its payload. Doc 03 §4 says the client rebuilds the event "from the SSE fields plus `data`", but `at` and the event `id` aren't SSE fields, and the reducer needs `at` (message `createdAt`, session `updatedAt`). Doc 03 §4 is updated to match.
- **Global stream.** Has no replay.
- In M1b nothing publishes to session channels. The live half is wired anyway and covered by a bus-level test that publishes synthetic events.

### D10. Idempotency is ASGI middleware backed by `idempotency_keys`
The middleware applies to `POST` requests that carry `Idempotency-Key`:
1. It hashes the body (SHA-256).
2. In one writer transaction, it looks the key up:
   - **missing:** insert `in_flight` and continue;
   - **`done` with the same hash:** replay the stored status and body;
   - **different hash:** respond 409 `conflict`;
   - **`in_flight`:** wait on a per-key `asyncio.Event` in process memory, then replay.
3. After the handler finishes, it stores the status and body as `done`.

Startup deletes any leftover `in_flight` rows (that process died) and expired rows. A missing header simply passes through.

### D11. Errors
- `api/errors.py` defines `HorizonHTTPError(code, message, status, retryable=None, details=None, retry_after=None)` plus handlers for:
  - `HorizonHTTPError`;
  - `RequestValidationError` → 422 `validation`, with `details.fields`;
  - Starlette 404 → `not_found`;
  - 405 → `validation`;
  - anything unhandled → 500. The code is `provider_error`, the only 5xx code in the enum. The message is generic, and the exception is logged with the `request_id`.
- The default `retryable` comes from the same table as `errors.ts` `DEFAULT_RETRYABLE`, and a unit test compares the two.

### D12. Reset-demo and factory reset
- **Reset-demo** runs in one writer transaction, so readers never see a half-reset world:
  - **Seed worlds and characters:** upserted by ID. A tombstoned or archived seed character comes back as shipped.
  - **Seed assets:** seed-batch asset rows of seed characters are re-inserted, and their non-seed versions are deactivated, never deleted (OQ-13).
  - **Seed sessions:** deleted (the cascade takes events, messages, traces and citations) and re-inserted through the D5 path.
  - **Seed ledger rows:** `is_seed` rows are replaced.
  - **Memory and knowledge:** `is_seed` memory and knowledge of seed characters are replaced, and user-earned memories (`is_seed = 0`) are kept.
  - **Purge outbox:** an `ai_purge_queue` row (`scope:'session'`) is written for the seed session IDs.
  - **Event:** `mock.reset` is published after the commit.
  - A seed world deleted by the user is simply re-inserted. Its user forks were already gone with it.
- **Factory reset** follows doc 02 §4:
  1. set a lifecycle gate, so new requests wait on an `asyncio.Event`;
  2. close the bus subscribers;
  3. dispose both engines;
  4. detach and close the file log handler;
  5. `rmtree` everything in `data/` except `models/`, retrying 5 × 200 ms with a chmod-on-error hook for Windows read-only and lock errors;
  6. re-run the lifespan steps;
  7. release the gate.
- **CLI.** `horizon reset` = reset-demo. `horizon reset --factory --yes` = factory reset, run offline (when no server is running).

### D13. Test mode
`HORIZON_TEST=1` does four things:
- mounts `/_test/*`;
- turns on response validation (D1);
- loads the default-scenario `_mock` overlays at seed time (OQ-6);
- lets the data directory be overridden through `HORIZON_DATA_DIR`, so each test run gets a temporary one.

The test routes:
- **`/_test/clock`:** `{ freezeAt?: string, advanceMs?: number }`.
- **`/_test/scenario`:** a registry that is empty in M1b. Every ID returns `validation` with `details.availableIn`.
- `ai-profile` and `decider-fixtures` arrive with M2 and M3.

### D14. The HTTP harness and milestone gating for the portable suite
- **Gating.**
  - `clientContract.portable.ts` gains a `type Milestone = "M1b" | "M2" | "M3" | "M4" | "M5" | "M6"`.
  - Each test is declared with `test(m: Milestone, name, fn)`.
  - A harness declares `supports: Milestone | "all"`, and the mock harness declares `"all"`.
  - A test above the harness's milestone is registered as `it.skip(\`[pending ${m}] ${name}\`)`.
  - An unknown milestone throws when the suite is defined, which makes the suite fail.
- **Splitting and adding tests.**
  - "queries work without a key" splits into a read half (M1b) and a `missing_key` half (M3).
  - The read half of the knowledge test becomes its own M1b test, which accepts `indexed | keyword_only` (OQ-1).
  - New portable M1b tests:
    - world create/rename/delete;
    - duplicate and reserved names;
    - reset restores a renamed or deleted seed world and keeps a user world;
    - `subscribe(sinceSeq)` on a seed recording;
    - `messages == reduce(events)` for every seed session (it imports `engine/sessionReducer`, not the mock).
- **The HTTP harness.**
  - It lives in `clientContract.http.test.ts` and uses its own `vitest.http.config.ts` with a `globalSetup`. That setup starts `uv run --project ../backend horizon serve --port 8765` with `HORIZON_TEST=1` and a temp `HORIZON_DATA_DIR`, waits for `/health`, and kills the server on teardown.
  - Each `makeHarness()`:
    - calls `POST /admin/factory-reset`, which gives a fresh dataset (OQ-10);
    - freezes the clock at the mock harness's `START`;
    - returns `{ client: new HttpClient({ baseUrl, EventSource }), advance: /_test/clock, setScenario: /_test/scenario, reset: client.admin.resetDemo(), setKey: throws "pending M2" }`.
  - Node 24 has no `EventSource`, so the harness injects one from the `eventsource` npm package (dev dependency).
- **Where it runs.** `npm test` stays Python-free. The HTTP run is `npm run test:http` in `frontend/` and is part of the root `npm test`.

### D15. HttpClient structure
- **Location:** `frontend/src/client/http/`.
  - **`transport.ts`:**
    - `fetch` wrapper;
    - base URL;
    - JSON in and out;
    - envelope → `HorizonError`;
    - a `TypeError` from fetch → `network`;
    - `Idempotency-Key` from `crypto.randomUUID()` per call, reused when the transport retries a lost response (one retry, for `network` errors only).
  - **`paging.ts`:** `collect(path)` follows `nextCursor`.
  - **`sse.ts`:**
    - `GlobalStream`: one shared `EventSource`, ref-counted by `onGlobal` subscribers;
    - `SessionStream`: one at a time, which closes the previous one, delivers events in `seq` order and drops `seq ≤ last`.
    - The `EventSource` constructor is injectable.
  - **`HttpClient.ts`:** implements `HorizonClient`. Methods for later milestones call `notYet("M3")` and the like, which throws `HorizonError("validation", "Not available on the local backend yet.", { details: { availableIn } })` without sending a request (OQ-8).
- **`client/index.ts`:**
  - `const impl = import.meta.env.VITE_HORIZON_CLIENT === "http" ? new HttpClient({ baseUrl: "/api/v1" }) : new MockClient()`;
  - `mockDev` is `null` under HTTP.
  - `frontend/.env.http` (committed, no secrets) holds `VITE_HORIZON_CLIENT=http`, and `vite --mode http` picks it up. That avoids `cross-env` on Windows.
- **Reset buttons.** `admin.resetDemo()` is added to `HorizonClient`:
  - MockClient: delegates to the existing `dev.resetDemoData` logic;
  - HttpClient: `POST /admin/reset-demo { confirm: true }`.

  `SettingsScreen` and `WorldSelectScreen` call `client.admin.resetDemo()`. The mock-only MockSwitcher keeps its own button.

### D16. Mock parity for world names
`MockClient.worlds.create` / `update` add:
- the unique-name check (case-insensitive, trimmed);
- the reserved check against the shipped seed world names, using the names from the loaded seed dataset.

Both reject with `conflict` and `details: { field: "name" }`. The existing behaviour (trim, 40-character cut, `New World` fallback) is kept, and the backend copies it.

### D17. Root workspace and the dev loop
- **Root `package.json`** (devDependency `concurrently`):
  - **`setup`:** `npm ci && npm ci --prefix frontend && uv sync --project backend`.
  - **`setup:docling`:** `uv sync --project backend --group docling`. `horizon models fetch` is added in M5. Until then, `/health` reports `models_missing` after this step.
  - **`dev`:** `concurrently -k -n api,web "uv run --project backend horizon serve --reload" "npm run dev --prefix frontend -- --mode http"`.
  - **`demo`:** `npm run build --prefix frontend -- --mode http && uv run --project backend horizon serve --static frontend/dist`.
  - **`test`:** `uv run --project backend pytest && npm test --prefix frontend && npm run test:http --prefix frontend`.
- **Vite** gets `server.proxy` entries for `/api` and `/assets/gen` → `http://127.0.0.1:8000`, with `changeOrigin` and no response buffering. The existing `seedAssets` plugin keeps serving `/assets/placeholder/**`.
- **Python** is pinned with `backend/.python-version` = `3.12` and `requires-python = ">=3.12,<3.13"`. uv downloads a managed CPython 3.12, and the system 3.13 is untouched (OQ-4).

### D18. Logging and IDs
- **Logging.**
  - Uses stdlib `logging` with a small JSON formatter (no extra dependency).
  - A `RedactFilter` matches `sk-or-[A-Za-z0-9_\-]+` on the message, the args and the exception text.
  - A `RotatingFileHandler` writes 5 × 5 MB, alongside a console handler.
  - A `request_id` is held in a contextvar set by middleware.
- **IDs.** `ids.new_id(prefix)` = `f"{prefix}_{ULID()}"`. A ULID is Crockford base32, which fits `^prefix_[0-9A-Za-z]{1,40}$`.

### D19. Job reads ship in M1b
`GET /jobs/{id}` and `GET /jobs?active=true` are reads over tables that already exist. The profile `JobPill` calls `jobs.listActive()` on every profile it opens, through `useActiveJobs`, and the portable `not_found` test needs `jobs.get`. `jobs.subscribe` and every job write stay in M4 (OQ-9).

## Risks / Trade-offs

- **[sqlite-vec doesn't load under aiosqlite on Windows]** → Spike (a) runs first. If it fails, stop and record it here as a blocker. A sync `sqlite3` loader thread is not quietly substituted.
- **[FTS/vec triggers don't fire on FK cascades]** → Spike (b). The fallback (explicit index deletes in repositories) would change D3/D4, so a failure stops the change for a decision.
- **[`pytorch-cpu` index resolution fails, or a lock makes `uv sync` slow]** → Spike (c) only locks. The `docling` group is optional and never synced by `setup`.
- **[`uvicorn --reload` + `concurrently` on Windows leaves an orphan Python process]** → `-k`, plus a manual Ctrl-C check in the tasks. If it reproduces, `dev` runs without `--reload` and with a `dev:reload` variant.
- **[Factory reset per portable test is slow]** → It's fine for about 8 M1b tests (~1 s each). If later milestones make it slow, add `/_test/reset` (truncate + re-seed), which is OQ-10's alternative.
- **[A static import of both clients grows the Vercel bundle]** → `import.meta.env` is constant-folded, so the dead branch is removed. `npm run budget` must stay green on the mock build. If it isn't, switch to a `virtual:horizon-client` module alias chosen at build time.
- **[The new world-name rule breaks an existing E2E or unit test that reuses names]** → Run the full E2E suite. Fix the test data, not the rule.
- **[Seed reduce-and-assert finds a real divergence between the TS reducer and the shipped `messages.json`]** → That would be a seed-build bug. Fix the seed build so the TS side stays green, and never weaken the assertion.
- **[The "frozen in demo mode" energy hides regen bugs until M2]** → The shared fixtures already cover regen in both languages.

## Migration Plan

- There is no data migration: this is the first database.
- **Developers:** run `npm run setup` once, then `npm run dev`.
- **Vercel:** unaffected (explicit `installCommand` / `buildCommand`, mock default).
- **Rollback:** the change is additive. `VITE_HORIZON_CLIENT` unset means the mock, and the backend folder can be ignored. The branch merges to `dev` by squash after archive.
- **Docs updated in this change:**
  - doc 05 rev 1.3 addendum (`admin.resetDemo`, already listed in doc 03 §7);
  - doc 03 §3 (job reads in M1b, test-mode overlays, `/_test/scenario` registry);
  - doc 06 (the branch-per-milestone rule; job reads moved to M1b);
  - doc 02 §5 (`_mock` is imported in test mode only);
  - root README "Run locally".
