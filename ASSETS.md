# Assets

Where every asset Horizon ships comes from, and under which licence. Settings → About links here.

**The seed characters' portraits and theme songs are AI-generated** (the v1 endgame's real demo): each portrait was made once in the app itself, through the same paths a user's character takes (two candidates from Seedream 5.0 Flash, one locked as the base, then one edit of it per emotion and a blink frame), and each theme is one Lyria 3 Clip. `horizon demo export --assets` copied them into `seed/assets/`; the prompts behind them are in `frontend/scripts/seed-build/recorded/` (`images.json` holds each character's appearance, which `backend/horizon/ai/image_prompt.py` compiles into the prompt; `songs.json` holds each song's prompt). The system tracks are still WebAudio sketches made by Horizon, released as CC0 by `seed/system-tracks.json`.

## How to read the table

| Column | Meaning |
|---|---|
| Pattern | A repo-relative path glob (`**` spans folders), `npm:<package>` for a bundled font, or `track:<id>` for a system track in `seed/system-tracks.json` |
| Source | `procedural`: made by Horizon (code-generated or authored in this repo). `ai`: generated by a model. `library`: a third-party asset (e.g. a CC0 pack). `font`: a bundled typeface |
| Credit / provenance | Who made it. An `ai` row must name `model=`, `date=`, `prompt=` (a path to the prompt) and `technique=` (base, edit or sheet), separated by `;` |
| Licence | An SPDX identifier |

`npm run assets:check` (in `frontend/`, and in CI) fails if a shipped file has no row, a row matches nothing, or a row lacks a required field. Not shipped, so not listed: anything under `data/` (what you generate locally) and `docs/` (e.g. the image-model test results).

**Sound effects** have no files: they are synthesised at runtime in `frontend/src/audio/synth/` (procedural, MIT).

## Generated music

Theme songs made with Lyria 3 Clip (through OpenRouter) are AI output under Google's terms, read 2026-10-10 ([doc 12](docs/ai/12-images-music.md) I8, [group A](docs/ai/checks/group-a.md) A4):

- **The terms.** These are the [Gemini API Additional Terms](https://ai.google.dev/gemini-api/terms) (effective 2026-03-23). Google claims no ownership of what you generate, and it may generate the same or similar content for others. You are responsible for how you use the output and for complying with the law. The terms set no music-specific restriction and no attribution duty. OpenRouter passes the provider's terms through.
- **The watermark.** Every Lyria clip carries Google's inaudible **SynthID** watermark ([music generation docs](https://ai.google.dev/gemini-api/docs/music-generation), updated 2026-10-01).
- **Your songs.** A song you generate in Horizon is under those terms. It lives under `data/` and isn't shipped, so it has no row above.
- **The seed themes** are seven Lyria clips, one per character with a song brief, committed under `seed/assets/themes/` (the `ai` row above). Google claims no ownership of them; Horizon ships them under the repository's MIT licence, and Google's terms above still apply to their use.

## Generated images

The seed portraits were made with ByteDance's Seedream 5.0 Flash through OpenRouter (D-61), under the provider's terms as OpenRouter passes them through (see the model's page on OpenRouter). Horizon ships them under the repository's MIT licence. Every prompt carries the adult and originality lines of the image prompt compiler (doc 12 I1); the characters are original and adults (doc 06). A portrait you generate in Horizon lives under `data/` and isn't shipped.

**Regenerating a seed portrait or theme.** Regenerate it on the demo instance, the app the demo was made on, served on port 8010 (`HORIZON_DATA_DIR=<its data folder> uv run horizon serve --port 8010` in `backend/`), accept the new version, then run `npm run demo:assets` from the repo root while it runs: it exports every seed character's active portraits and theme from port 8010 into `seed/assets/` and rebuilds `seed/`. Your everyday app on port 8000 is never read, so testing there never reaches the demo (`horizon demo export --from <url>` picks another app).
